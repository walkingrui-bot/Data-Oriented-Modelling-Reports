# Data-Oriented Modelling — Reports

## What Data-Oriented Modelling means

Data-Oriented Modelling studies how observations are generated, how measurement changes the structure we see, and how this evidence can determine the design of a model. Our working principle is to measure the data-generating and observation processes, identify what stays stable and what changes with state or context, and translate that measured structure into computation. We begin with each source’s own observation units, statistical form, chronology and uncertainty; map its geometry and dependencies; and measure how local changes affect relevant responses. Stable relationships support direct mathematical mappings. Changing relationships motivate state, memory and mechanism updates. Additional computation earns its place through repeatable structure and validation on held-out entities, trajectories or sources. Specialist models can then coordinate through consequences shared across their different observations. The aim is precise prediction and useful decisions grounded in the particular data: **model design itself becomes an outcome of data analysis.**

**Measure how the world produces observations → identify stable and changing mechanisms → build the computation supported by those measurements.**

The basic experimental question is concrete: when we change a word, follow a molecular edit, add a patient’s history or alter an agent’s routing, what changes in the subsequent response? Matched observational comparisons measure conditional relationships; controlled interventions test the role of a manipulated component. Together, they help locate transferable operations, state-dependent changes, useful memory and the information that must survive learning. Direct statistics and mathematical models provide the first description; learned components take on the roles established by that analysis.

Precision modelling develops the sampling, transformations, state variables, objectives and computational structure around a particular dataset. General-purpose coordination provides a complementary layer: local models retain their native measurement structures while shared consequences constrain a common inferred state. Stable measurement mechanisms and faster changes in channel state receive distinct computational roles. Evidence referring to the same reality at the same time is coordinated as a set; observations of a changing world retain their chronology.

For decision-making agents, this extends into a complete control cycle: **observations → inferred state → eligible actions → action commitment → execution feedback → updated state**. Information, action eligibility and the measured consequences of execution each have an explicit role. Across these research lines, we are making **when to build which model** into an experimental question.
