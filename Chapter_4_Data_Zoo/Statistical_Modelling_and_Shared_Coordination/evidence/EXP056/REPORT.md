# EXP056 报告：共享矩阵容量是否太小

研究 ID `STAT-PSYMOE-EXP056-20261002-001`；只读回顾性审计；2026-10-02。

**结论：目前不知道。** 原共享模型的core确为16×16（含偏置272参数），整个六路网络约769参数。模型不大，但“大小”与“容量不足”是两个不同命题。原实验没有同数据、同训练和同验证策略下的维度对照；三个seed都在1000 epoch预算上限取得最佳验证成绩，最后一轮还在缓慢下降。早期250-epoch运行三seed均差于Stat-MoE，长预算后才有很小点估计优势，这使优化预算成为实际竞争解释。[结构和轨迹原位证据](EVIDENCE_MATRIX.md)。

在原26.06药物任务，16D Ganglion相比Stat-MoE的已用test log-loss点差为−0.001361，但232个target分组的95%区间[−0.004207,+0.001225]跨零。核心权重增量有效秩约3.3/16不能决定最佳矩阵宽度。来源样本/事件支持、历史时锁、既有test暴露仍阻断可确认的药物容量结论。[EXP017原报告](../EXP017/REPORT.md)与[EXP018–022证据](EVIDENCE_MATRIX.md)。

在PADS，人级双通道静息任务未过事前联合门；后续心算任务缺兼容独立外部cohort，尚无Ganglion容量试验。在空气质量任务，一种同刻跨站均值特征未达预定增量门；而固定小ridge加全年本地历史在已暴露四城2015评价均过门，说明至少该问题无需先通过增加本地模型容量来解释已观察的变化。这都不直接裁决共享矩阵。[跨任务证据](EVIDENCE_MATRIX.md)。

**行动决策：** 不以扩宽共享矩阵作为当前默认修复。下一项值得投资的是一个真实、可按时间或来源独立评价、且开发域中传统联合基线仍留有稳定跨通道增量的问题；一旦存在，另立ID固定同条件小/原/大共享宽度、训练到可判断收敛、用验证选择并保留未见外部评价。若容量梯度在验证无额外价值，应保留统计模型；若有稳定增益，再允许做一次独立评价。此项是未来实验设计条件，不是已执行结果。

本轮实际验证只读局部源代码、三条原训练trace、局部JSON和具名旧报告，并核对数值/结构；未训练、不加载检查点、不重新打分测试。未验证：16D充分收敛、8D/32D结果、新外部cohort、任何新的科学泛化结论。冻结门见[GATE_RESULT.md](GATE_RESULT.md)，尝试账见WORKLOG.md (source asset outside this public snapshot)。
