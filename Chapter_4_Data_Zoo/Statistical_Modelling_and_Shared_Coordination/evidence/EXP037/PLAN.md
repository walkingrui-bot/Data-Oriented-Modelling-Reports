# EXP037 — MyGait 同文件双足 IMU 字段语义预检

研究 ID `STAT-PSYMOE-EXP037-20261002-001`；2026-10-02；`EXPLORATORY_SOURCE_AUDIT`；父阶段 [EXP036](../EXP036/CLOSEOUT.md)。用户 2026-10-02 路线自治授权适用。本实验问：官方 MyGait `1_10mSlow` 的**单人 CSV 内**能否直接识别左右足的真实 IMU 行和时间顺序？EXP036 的文件名双足门已停止，不在这里追认通过。

## 依据、竞争解释和决策

官方 [Zenodo v1](https://zenodo.org/records/15672744) 描述一人一任务 CSV、`foot` 字段与 50 Hz 双足 IMU；正式 API 给 `cc-by-4.0` 和原 ZIP 地址。EXP036 路径索引发现 PD44、健康45，各一份 `1_10mSlow` CSV，文件名本身不含左右。可能 CSV 内有两足可分行，也可能 `foot` 字段缺失、单足或编码不可判。前一种情况值得做全部89人数字来源资格，后一种情况应停止这条双足任务。两种结果会改变工程决定。

## 冻结样本、方法和门

- 固定原件：EXP036 `SOURCE_METADATA.json` 指向的官方单一 ZIP；只按 HTTP Range 读取尾部中央目录与 **PD01、健康01** 的 `1_10mSlow` CSV 压缩条目。两人是结构预检单位，不代表整队列；不选结果较好的文件替换。
- 从 ZIP 本地头定位原件条目，在内存解压与逐行读取，不保存 ZIP/原始 CSV 副本。只保留派生字段名、足侧取值、逐足行数、时间值和 IMU 数值的可解析诊断。压力 `p_...` 永不用于本任务。
- `STRUCTURE_PASS` 要求两份各有 `foot`、可明确识别左右两类值（大小写无关的 `left/right` 或 `L/R`）；左右各≥100行；存在时间戳与各足至少三轴加速度和三轴陀螺字段；这些列逐行可解析有限数，逐足时间严格递增。时间单位如未明，只记录原值和步长，不推定 50 Hz。任何条件不满足或原件范围读取不可用，标 `STOP_SOURCE_STRUCTURE`；不补样、不改门。
- 仅在结构门通过后，另立新 ID 审全部89人及临床关联；本轮不做模型或人群支持率结论。若停止，根据本次失败层级另立新问题。

## 预算和预期输出

最多1次 4 MiB ZIP 尾部 Range 与2次各≤1 MiB 条目 Range；最多3次 ZIP 源请求，读取≤6 MiB 压缩原件。单人一份文件；当前没有模型状态、随机种子或训练。环境：本机 Python 标准库、公开 Zenodo HTTPS。结果位于本目录 `SOURCE_AUDIT.json`、`WORKLOG.md`、`GATE_RESULT.md`、`REPORT.md`、`CLOSEOUT.md`；原始源留在原地址。局部验证只核本实验文件与原件读取诊断，不运行全仓门或哈希。
