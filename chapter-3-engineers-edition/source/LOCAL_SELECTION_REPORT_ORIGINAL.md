# 哪一种工具选择方法更适合：进一步探索的实测结果

MCD-SELECTION-20260926-002；2026-09-26；父MCD-ENGINEERING-20260926-001。已完成六方案开发、冻结校准、100题比较，以及独立登记的40题改述压力测试。原实验材料和权重全部原路径引用，无训练、无重复包。

**更适合当前任务的做法，是先建立可信的“用户请求—工具能力”匹配评分，选择之后再处理参数与执行条件。内部控制几何可以解释这个行为，但它本身不能替代语义选择能力。**

这一结论来自实际对照：同一135M模型只换读出接口没有解决问题；专门训练过文本相关性的小模型和简单词面匹配都远好于原来的标签读出。在本组直白英文任务上，复杂神经方法并没有超过简单基线；措辞变化才暴露出二者的差别。

## 先把三种可能原因分开

H1：是不是读取A/B/C的接口错配？保持135M权重，分别用原标签读出、给assistant预填明确标签前缀、逐工具独立Yes/No评分。

H2：是不是任务适配程度不够？引入官方 [MS MARCO MiniLM-L6-v2](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2)。这是经过query-passage相关性训练的22,713,601参数模型，不是工具执行模型。本机使用原始logit作关系评分、canonical名字由代码映射，模型不生成执行句柄。

H3：会不会根本不需要神经模型？加入TF-IDF词面余弦，IDF只用开发题候选说明计算，没有测试标签参与。不能只赢一个不合适的基线就宣布新方法先进。

模型选择、schema和权限接口是不同问题。使用[官方135M指令模型](https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct)并不自动意味着它接受我们设定的多选读出；该模型卡对function calling专项能力的声明属于1.7B版本。本轮也没有改变AIA主模型。

## 六种方案的开发结果

使用上一轮已见的multiple_0..29做开发，不把这些题当新确认。

| 方法 | 正确数 | 反转候选后选择同一工具 |
|---|---:|---:|
| 135M原A/B/C接口 | 12/30 | 1/30 |
| 135M加明确标签前缀 | 13/30 | 1/30 |
| 135M逐工具Yes/No | 8/30 | 30/30 |
| 22.7M关系评分：名字+描述+schema | 30/30 | 30/30 |
| 22.7M关系评分：仅描述 | 29/30 | 30/30 |
| 词面TF-IDF匹配 | 28/30 | 30/30 |

逐工具评分可以在结构上消除候选展示顺序干扰，但**顺序稳定不等于判断正确**：135M Yes/No就是反例。前缀改写也不是充分修复。这里没有把失败解释成“函数视角错了”；失败的是特定模型/读出与任务的配合。

随后冻结四个最终方案：神经full排序器、原标签、前缀标签、词面基线；独立30题校准，100题测试。详见[冻结协议](FROZEN_PROTOCOL.md)。不看测试结果再选方案。

## 100个未参与开发的题目

测试为固定公开BFCL multiple_60..159，沿用001下载的原件；答案只用于结果评价。未训练模型，公开题预训练暴露未知；任务/模板相关性存在，不称完全独立自然用户抽样。

| 冻结方法 | 正确数 | 说明 |
|---|---:|---|
| 135M原标签 | 40/100 | 接口资格仍不足 |
| 135M前缀标签 | 37/100 | 开发集微小改善没有迁移 |
| 22.7M关系评分 | **99/100** | 当前语义候选排序有效 |
| 词面匹配 | **99/100** | 本批任务已被简单方法基本解决 |

99/100的Wilson 95%区间为94.55%—99.82%，只是在任务独立性假设下的描述性区间。神经排序器相对原标签，59题独赢、0题独输，精确配对p≈3.47×10⁻18；满足事先设定的“高至少10个百分点且p<.05”。相对词面则无任何逐题优势，p=1。

二者唯一未正确选择的题都是multiple_153：询问《里斯本条约》签署时间。细节不同：神经排序器三个分数都约−11，强制选了熵变工具；词面三个分数全零，返回并列、不选择。**“所有选项都不匹配时仍取最大值”是需要单独处理的故障。** 它不能靠排名第一这个事实消除。

未复制原题，逐题分数与选择见[test_scores.jsonl](test_scores.jsonl)，汇总见[test_summary.json](test_summary.json)。测试未发生token截断。

## 行为对照：它是否使用query，是否受位置支配

100题上另跑固定两方法、三个配对条件；这些是同任务派生状态，不算新增独立样本。

| 对照 | 22.7M关系评分 | 135M前缀标签 |
|---|---:|---:|
| 实际逆序候选仍选同一canonical工具 | 100/100 | 7/100 |
| 把query换成另一个候选的功能描述，转选该工具 | 100/100 | 61/100 |

第二项是构造的功能说明匹配正控，不能混入自然任务准确率。独立query/tool评分的顺序不变部分来自设计，实测用于确认实现没有把位置混进canonical映射。它提供比“四种删信息视图都同意”更贴近所需行为的检查。

## 无匹配与拒答：有效，但代价很大

在multiple_30..59上，先构造30原任务和30移除正确工具的派生条件，再冻结分数/差距阈值：`top_score >= 3.2334132`，且有多个候选时 `top1-top2 >= 1.3862090`。单候选只检验绝对分数。校准60条件接受13、正确12/错误1，符合当时设定的经验错误率<=10%与最少接受10项。

不改阈值，应用到最终100题及100个移除gold条件：

- 原任务接受38/100，38项全正确。
- 100个移除正确工具的条件全部拒答，误接受0/100。
- 同时拒掉61个原本能排序正确的任务。

这说明当前策略的用法是保守候选筛查，代价是只有38%覆盖。零观测错误不等于未来风险为零；移除gold也只是在基准答案定义下构造的困难负例，不能证明剩余工具在所有现实语境都无用。

**不能把这组数值当通用阈值。** 新CLI默认只返回排序，必须显式传入policy才应用这项实验校准；输出最多是`CANDIDATE_FOR_BINDING`，没有EXECUTE。

## 词面饱和后，再做一组改述压力测试

原100题结果揭示新问题：高正确率可能主要来自词汇重合。因此另立[MCD-SEMANTIC-STRESS-20260926-003](../MCD-SEMANTIC-STRESS-20260926-003/REPORT.md)，使用此前未用的multiple_160..199。在只读query、不看候选/gold的条件下编写40条含义保持改述，先冻结，再比较原两个方案，未训练或调阈值。

| 输入 | 神经排序 | 词面匹配 |
|---|---:|---:|
| 40个原问题 | 40/40 | 40/40 |
| 40个改述 | 38/40 | 34/40 |

query与gold文档的内容词重合均值从53.99%降到21.75%。神经方法多正确4例，但精确配对p=.125，样本不足以确认总体优势。不能把这个小差异包装成普遍胜出。

更关键的是拒答覆盖：父阈值在原40题接受12，在改述只接受2，均没有观测到错误。**阈值随表面表达发生覆盖漂移；仅报告接受集准确率会隐藏实用性损失。** 本轮没有在这些测试题上重调阈值救成绩。

## 现在什么更适合

| 需求 | 本轮支持的选择 | 边界 |
|---|---|---|
| 工具少、术语统一、请求措辞标准 | 先用简单词面匹配并显式保留无匹配/并列 | 本批100题与神经模型持平；不宣称能理解任意同义词 |
| 请求来自自由措辞、近邻工具说明相似 | 独立query/tool关系评分值得采用 | 40改述中数值较好；相对优势仍需更多独立材料确认 |
| 决定是否可以自动执行 | 语义匹配、参数绑定、权限/前置条件、后果验证分开 | 本轮只有排序和实验拒答，未验证完整执行系统 |
| 解释已经测得的错选 | 用输入对照和有限内部干预定位 | 隐藏轴/半径不能代替基本任务正确性与无匹配识别 |

推荐接口顺序是：**请求与工具能力匹配 → 选出候选或弃权 → 绑定参数 → 检查权限及环境 → 执行并验证结果**。缺少参数时，相关工具仍可以是候选，下一步应ASK；不能因为参数暂未齐全就把它当成语义不相关。不存在对应工具则走无匹配路径；不是去已有工具中硬找一个最大值。

这比直接让小型生成模型输出候选字母更贴近本任务，也比把内部几何直接接成放行门更有依据。它保留了原报告“状态条件下的可执行函数”视角，但把函数的行为合同和读出资格放在几何解释前面。
